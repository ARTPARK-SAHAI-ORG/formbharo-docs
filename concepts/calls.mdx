---
title: "Calls"
description: "One conversation with one person, and the answers it produced."
---

A call is one conversation between an agent and one person. Everything that conversation
produces is filed under a conversation id that you choose before the call starts.

A call row looks like this:

```json
{
  "conversation_id": "6f1f0a1c-1111-4b0c-9a3a-2b6f9c0d0001",
  "source": null,
  "caller_number": null,
  "form_data": {"consent": true, "full_name": "Asha Rao", "has_fever": "Yes", "phone": null},
  "form_status": {
    "consent": "answered",
    "full_name": "answered",
    "phone": "skipped",
    "has_fever": "answered",
    "fever_started_on": "empty",
    "fever_symptoms": "empty"
  },
  "filled_fields": 4,
  "total_fields": 6,
  "status": "in_progress",
  "created_at": 1787626888.006087,
  "duration_secs": null,
  "cost": null,
  "has_recording": false,
  "has_transcript": false,
  "avg_ack_latency_secs": null,
  "avg_ack_to_reply_secs": null
}
```

| Field | What it is |
| --- | --- |
| `conversation_id` | The id you chose for this call. |
| `source` | Where the call came in from, such as `twilio` or `exotel`. It is `null` for a call from a browser. |
| `caller_number` | The phone number that called, when there is one. |
| `form_data` | The answers. See [Answers](/concepts/answers). |
| `form_status` | How each answer got there. See [Answers](/concepts/answers). |
| `filled_fields` | How many questions are resolved, meaning answered or deliberately skipped. |
| `total_fields` | How many questions the agent has. |
| `status` | One of the four below. |
| `created_at` | The last time this call's answers were written, in unix seconds. Not when the call started. |
| `duration_secs` | How long the conversation lasted. `null` when there is no transcript to measure. |
| `cost` | What the call cost in US dollars, and the number of turns. `null` when nothing was measured. |
| `has_recording`, `has_transcript` | Whether an audio recording and a transcript were kept. |
| `avg_ack_latency_secs`, `avg_ack_to_reply_secs` | How quickly the agent responded, averaged over the call. `null` when nothing was measured. |

## The four statuses

<ResponseField name="in_progress" type="status">
  The call is still going, or it stopped so recently that FormBharo cannot tell yet. Not
  a failure.
</ResponseField>

<ResponseField name="complete" type="status">
  Every question that needed an answer got one. Questions inside a branch that never
  activated do not count, so a call can be complete with some questions left at `empty`.
</ResponseField>

<ResponseField name="screened_out" type="status">
  An answer meant the person did not qualify, so the agent stopped early on purpose. You
  set this up with `end_call_values` on a question. See
  [Question types](/reference/question-types).
</ResponseField>

<ResponseField name="failed" type="status">
  The call ended with the form still unfinished.
</ResponseField>

<Note>
In the analytics, `screened_out` counts towards `completed`, because the agent did the
job it was asked to do. See [Read the analytics](/guides/read-the-analytics).
</Note>

## Reading calls

- `GET /api/v1/agents/{agent_id}/conversations` lists one agent's calls, newest first.
- `GET /api/v1/conversations` lists calls across every agent you can see, newest first.
  This is the one to poll. See
  [Poll for finished calls](/guides/poll-for-finished-calls).
- `GET /api/v1/data/{agent_id}/{conversation_id}` returns just the answers for one call,
  and needs no key. This is the one to poll while a call is running.
- `GET /api/v1/agents/{agent_id}/conversations/{conversation_id}/transcript` returns what
  was said, in order.
