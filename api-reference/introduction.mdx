The FormBharo REST API is organized into resource groups: Agents, Calls, Analytics, and Workspaces. All endpoints are under `/api/v1` on your FormBharo server, with one exception: `POST /offer`, the WebRTC signalling path, which lives at the bare root.

## Authentication

Every request must include an `Authorization` header with your API key. See [API Keys](/getting-started/api-keys) for how to create one.

```http
Authorization: Bearer fb_live_0123456789ab_...
```

Running a call from your own page needs no key: `POST /api/v1/conversations` returns a conversation id and a token, and that token authorizes the audio connection and the answer poll. See [Run a Call](/guides/run-a-call).

<Note>
  Keep your API key secret. Never embed it in client-side JavaScript or expose it in a public repository. Rotate it immediately if it is compromised.
</Note>

## Base URL

Every example in this reference uses this address.

```text
https://api.formbharo.artpark.ai
```

All API paths are then appended after this base. For example:

```text
https://api.formbharo.artpark.ai/api/v1/agents
```

## Errors

| Code | Meaning |
| --- | --- |
| 401 | The `Authorization` header is missing, or the key is not valid. |
| 403 | The workspace or agent exists and your key may not use it. |
| 404 | The workspace or agent does not exist. |
| 422 | The request body failed validation. |

A 403 or a 404 carries the reason in an `error` field.

```json
{ "error": "You do not have access to this workspace." }
```

A key belongs to one workspace. A request for an agent or a workspace outside it returns 404, the same as an id that does not exist.
