import { FORMBHARO_URL } from "/snippets/formbharo-url.mdx";

<Steps>

  <Step title="Create a draft agent">
    `POST /api/v1/agents` always creates a draft. Send a `title` and a `questions` array. The response contains the `agent_id`.

    <CodeGroup>

    ```bash curl
    curl -X POST {FORMBHARO_URL}/api/v1/agents \
      -H "Authorization: Bearer <api-key>" \
      -H "Content-Type: application/json" \
      -d '{
        "title": "Clinic intake",
        "questions": [
          {
            "question": "What is your full name?",
            "response_type": "string"
          },
          {
            "question": "What is your date of birth?",
            "response_type": "date"
          }
        ]
      }'
    ```

    ```python python
    import requests

    response = requests.post(
        "{FORMBHARO_URL}/api/v1/agents",
        headers={"Authorization": "Bearer <api-key>"},
        json={
            "title": "Clinic intake",
            "questions": [
                {
                    "question": "What is your full name?",
                    "response_type": "string",
                },
                {
                    "question": "What is your date of birth?",
                    "response_type": "date",
                },
            ],
        },
    )

    agent = response.json()
    agent_id = agent["agent_id"]
    ```

    </CodeGroup>
  </Step>

  <Step title="Map each field to a question type">
    `response_type` sets how the spoken answer is parsed and stored.

    | `response_type` | What it stores | Extra options |
    |---|---|---|
    | `string` | Free-text answer | |
    | `number` | Numeric value | `number_format: "integer"` or `"decimal"` |
    | `date` | Date, stored as `DD-MM-YYYY` | |
    | `boolean` | Yes/no answer | `boolean_labels` to customise the spoken options |
    | `single-select` | One choice from a list | `options[]`, required |
    | `multi-select` | One or more choices from a list | `options[]`, required |

    `options` is an array of strings. The agent reads the list aloud and maps the answer to the closest option.

    Omit `number_format` to accept both integers and decimals.

    Add an optional `name` to a question to give it a stable snake_case key. Branch conditions reference questions by `name`.
  </Step>

  <Step title="Add scripts">
    Set `scripts` on the agent body.

    | Field | When the agent says it |
    |---|---|
    | `scripts.intro` | At the start of the call, before the first question |
    | `scripts.outro` | After all required questions are answered |
    | `scripts.outro_incomplete` | When the call ends before all questions are answered |

    `outro_incomplete` requires `outro`.

    ```json
    {
      "scripts": {
        "intro": "Hi, I'm calling on behalf of City Clinic to complete your intake form. This will only take a couple of minutes.",
        "outro": "That's everything I need. Thank you for your time, we'll see you at your appointment.",
        "outro_incomplete": "It looks like we ran out of time. Our team will follow up to collect the remaining details."
      }
    }
    ```
  </Step>

  <Step title="Add conditional branches">
    1. Add an entry to the top-level `branches` array with a unique `id` and a `condition`.
    2. Set `branch_id` on every question in that branch. Those questions are asked only when the condition is true.

    A condition supports these fields:

    | Field | Type | Meaning |
    |---|---|---|
    | `field` | string | The `name` of the question whose answer is evaluated |
    | `equals` | boolean | Matches the answer to a `boolean` question |
    | `present` | boolean | `true` asks the branch when the question was answered, `false` asks it when the question was skipped |

    `present` takes priority over `equals`. If both are set, `equals` is ignored.

    <CodeGroup>

    ```json Equals condition
    {
      "branches": [
        {
          "id": "has_insurance",
          "condition": {
            "field": "insurance_status",
            "equals": true
          }
        }
      ],
      "questions": [
        {
          "name": "insurance_status",
          "question": "Do you have health insurance?",
          "response_type": "boolean"
        },
        {
          "question": "Who is your insurance provider?",
          "response_type": "string",
          "branch_id": "has_insurance"
        },
        {
          "question": "What is your policy number?",
          "response_type": "string",
          "branch_id": "has_insurance"
        }
      ]
    }
    ```

    ```json Present condition
    {
      "branches": [
        {
          "id": "has_referral",
          "condition": {
            "field": "referral_source",
            "present": true
          }
        }
      ],
      "questions": [
        {
          "name": "referral_source",
          "question": "Were you referred by someone?",
          "response_type": "string"
        },
        {
          "question": "What is the name of the person who referred you?",
          "response_type": "string",
          "branch_id": "has_referral"
        }
      ]
    }
    ```

    </CodeGroup>
  </Step>

  <Step title="Configure screening">
    `end_call_values` is an array of strings. When the agent records any of those exact values, it ends the call and marks the conversation `screened_out`. Screened-out calls count as successes, not failures, and appear separately in analytics.

    ```json
    {
      "end_call_values": ["no", "not interested", "already completed"]
    }
    ```
  </Step>

  <Step title="Publish">
    `PUT /api/v1/agents/{agent_id}` always publishes. Send the complete agent body, not just the changed fields.

    <CodeGroup>

    ```bash curl
    curl -X PUT {FORMBHARO_URL}/api/v1/agents/AGENT_ID \
      -H "Authorization: Bearer <api-key>" \
      -H "Content-Type: application/json" \
      -d '{
        "title": "Clinic intake",
        "questions": [ ... ],
        "scripts": { ... },
        "branches": [ ... ]
      }'
    ```

    ```python python
    import requests

    agent_body = {
        "title": "Clinic intake",
        "questions": [...],
        "scripts": {...},
        "branches": [...],
    }

    response = requests.put(
        f"{FORMBHARO_URL}/api/v1/agents/{agent_id}",
        headers={"Authorization": "Bearer <api-key>"},
        json=agent_body,
    )

    if response.status_code == 400:
        print("Validation failed:", response.json()["validation_issues"])
    else:
        print("Published:", response.json())
    ```

    </CodeGroup>

    <Warning>
      On validation failure the API returns `400` with a `validation_issues` array. Fix every issue before retrying, partial saves are not supported.
    </Warning>
  </Step>

</Steps>

## Preview changes before saving

`POST /api/v1/agents/{agent_id}/diff-preview` takes a proposed agent body and returns an array of diff lines, each with a `type` field.

| Type | Meaning |
|---|---|
| `add` | Line present in the new version but not the current one |
| `remove` | Line present in the current version but not the new one |
| `context` | Unchanged line shown for context |
| `hunk` | Separator between diff sections |
| `meta` | Header information about the diff |

```bash curl
curl -X POST {FORMBHARO_URL}/api/v1/agents/AGENT_ID/diff-preview \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{ "title": "Clinic intake", "questions": [ ... ] }'
```
