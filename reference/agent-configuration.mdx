---
title: "Agent configuration"
description: "Every field you can send when you create or update an agent."
---

`POST /api/v1/agents` and `PUT /api/v1/agents/{agent_id}` take the same body. Only
`title` and `questions` are required.

```json
{
  "title": "Clinic intake",
  "description": "Booking a patient in before they see a doctor.",
  "language": "English",
  "agent_speaks_first": true,
  "scripts": {
    "intro": "Hello. I have a few questions before your appointment.",
    "outro": "Thank you. That is everything.",
    "outro_incomplete": "Thank you. We will not go any further today."
  },
  "questions": [
    {
      "name": "full_name",
      "question": "What is your full name?",
      "response_type": "string",
      "required": true
    }
  ],
  "branches": []
}
```

## Top level

<ResponseField name="title" type="string" required>
  The agent's name. Shown in listings.
</ResponseField>

<ResponseField name="questions" type="Question[]" required>
  The questions, in the order they are asked. See
  [Question types](/reference/question-types).
</ResponseField>

<ResponseField name="branches" type="Branch[]" default="[]">
  Groups of questions that are only asked when a condition holds. See
  [Branching](/reference/branching).
</ResponseField>

<ResponseField name="description" type="string" default="">
  Background on what the call is for and who is on the other end.
</ResponseField>

<ResponseField name="ai_instructions" type="string" default="">
  Extra instructions for the agent that apply to the whole call.
</ResponseField>

<ResponseField name="agent_persona" type="string">
  Who the agent should be, for example `community health worker conducting a symptom
  interview`.
</ResponseField>

<ResponseField name="user_persona" type="string">
  Who the agent is talking to, for example `patient or caregiver answering about the
  patient`.
</ResponseField>

<ResponseField name="language" type="string">
  The language the call is held in, for example `English` or `Hindi`.
</ResponseField>

<ResponseField name="agent_speaks_first" type="boolean" default="true">
  Whether the agent opens the call or waits for the person to speak.
</ResponseField>

<ResponseField name="ask_questions_one_by_one" type="boolean" default="true">
  Whether the agent asks one question at a time.
</ResponseField>

<ResponseField name="mute_user_while_agent_speaking" type="boolean" default="false">
  When true, the person's microphone is off while the agent is talking, so nobody can
  cut in mid-sentence.
</ResponseField>

<ResponseField name="send_hearing_acknowledgements" type="boolean" default="true">
  Whether the agent says a short phrase to show it heard the answer, before it asks the
  next question.
</ResponseField>

<ResponseField name="hearing_acknowledgement_mode" type="string" default="fixed">
  `fixed` picks one of `hearing_acknowledgement_phrases` at random. `llm` lets the agent
  word it itself. Only read when `send_hearing_acknowledgements` is true.
</ResponseField>

<ResponseField name="hearing_acknowledgement_phrases" type="string[]">
  The phrases `fixed` mode picks from. Sending a list where every entry is blank is
  rejected, because the agent would then say nothing.
</ResponseField>

<ResponseField name="scripts" type="Scripts">
  The exact words the agent says at the start and the end. See below.
</ResponseField>

<ResponseField name="workspace_id" type="string">
  The workspace to create the agent in. You must administer it. Only read when the agent
  is created; `PUT` ignores it. Leave it out for your personal workspace.
</ResponseField>

## scripts

<ResponseField name="scripts.intro" type="string">
  What the agent says to open the call.
</ResponseField>

<ResponseField name="scripts.outro" type="string">
  What the agent says when the form is finished.
</ResponseField>

<ResponseField name="scripts.outro_incomplete" type="string">
  What the agent says when the call ends early, such as when an answer screened the
  person out. Sending this without `outro` is rejected.
</ResponseField>

## Reading the configuration back

`GET /api/v1/agents/{agent_id}` returns the agent as it is stored, which is not the same
shape as what you sent. Each question is stored with `label` in place of `question` and
`type` in place of `response_type`:

```json
{
  "title": "Clinic intake",
  "questions": [
    {
      "name": "full_name",
      "label": "What is your full name?",
      "type": "string",
      "required": true
    }
  ],
  "branches": [],
  "context": "Booking a patient in before they see a doctor.",
  "validation_rules": "",
  "instructions": "",
  "agent_speaks_first": true,
  "ask_questions_one_by_one": true,
  "mute_user_while_agent_speaking": false,
  "send_hearing_acknowledgements": true,
  "hearing_acknowledgement_mode": "fixed",
  "status": "published",
  "updated_at": 1787626873.7724512
}
```

`description` is stored as `context`, and `ai_instructions` is stored as `instructions`.

`PUT /api/v1/agents/{agent_id}/config` writes that stored shape back directly, for
callers that would rather build it themselves. Most callers should use
`PUT /api/v1/agents/{agent_id}` and send the shape at the top of this page.

## Checking a change before you save it

`POST /api/v1/agents/{agent_id}/diff-preview` takes the same body as a save and returns
what would change, without saving:

```json
{
  "lines": [
    {"type": "meta", "text": "--- current"},
    {"type": "meta", "text": "+++ new"},
    {"type": "hunk", "text": "@@ -1,108 +1,21 @@"},
    {"type": "context", "text": " {"},
    {"type": "remove", "text": "-    \"title\": \"Clinic intake\","},
    {"type": "add", "text": "+    \"title\": \"Clinic intake v2\","}
  ]
}
```

`type` is `add`, `remove`, `hunk`, `meta`, or `context`.
`POST /api/v1/agents/{agent_id}/config/diff-preview` does the same for the stored shape.
